# 笔记写作指南

读者是下课后要复习的学生本人，**而且可能完全不看录像**。所以笔记有两个同等重要的要求：

1. **学得全**：只读这篇笔记，就能学到这节课讲的全部内容，包括老师的例题、逐步演示、推导、现场纠错、布置的作业和考试提示。时间链接是给想核对的人用的，不能拿来代替内容。
2. **读得顺**：像一个认真听课的同学整理的，直接写知识本身。它**不是**一份“关于这节课的报告”，也不是给审核者看的“我没有编造”的声明。

笔记建立在已保存的课堂资料（转写、截图、资料）之上，换模型或换风格时只需重新读学习包，不需要重新处理录像。

## 分层

1. **课堂资料层**（`lw process` 已保存）：带时间的转写、截图与 OCR、平台信息。不要改。
2. **课堂笔记**（`--kind lecture`，每个课时一篇）：按老师讲授的逻辑整理。
3. **按需产物**：复习提纲（`--kind review --key 第7周复习 -c 课程`）、知识卡片（`cards`）、专题（`topic`，如“关系代数除法”“实验三要求对照”）、针对一个问题的讲解（`explain`）。

## 课堂笔记的默认结构（可按课程调整）

```markdown
# 递归与回溯

- 递归 = 把问题拆成同类的更小问题 + 一个能直接解决的出口。
- 迷宫搜索按固定方向逐个尝试，走不通就退回上一个还有选择的位置。
- 递归调用靠工作栈保存每一层的参数、局部变量和返回位置。

## 1. 汉诺塔
（正文：定义、步骤、代码、例子）{t 10:10:59}
{f F003}

> [!tip] AI 补充
> 移动次数 T(n) = 2T(n−1) + 1 = 2ⁿ − 1。

## 2. ……

> [!question]- 自测（点开看答案）
> 1. 汉诺塔的两次递归调用里，柱子参数的顺序为什么不同？
>    答：……
```

- 开头 3–5 条要点，每条写**结论本身**（“X 是……”），不写“本节讲了 X”，也不必写“承接上一讲”。
- 小节按老师讲的顺序，标题写知识点名。
- “来源”（录像段、转写来源、截图数量、课表对应）由 `lw note save` 自动追加为折叠块，草稿里**不要**写“资料说明”。

## 怎样写全

- **按时间线逐段过一遍学习包**，每一段讲课都要在笔记里有着落。只有点名、闲聊、课间、设备调试可以略去。`lw note save --check` 会列出“讲了不少但笔记没引用”的时段，逐个回学习包核对。
- **例题和演示要能独立跟下来**：写出题目、每一步做什么和为什么、结果。老师在图上一步步走的过程（如迷宫怎么走、栈怎么变），用编号步骤或表格写出来，不要只写“老师演示了过程”。
- **屏幕上的内容要变成文字**：幻灯片上的定义、要点、表格、代码要写进正文，截图只是辅助；截图看不清时，读者手里就什么都没有了。
- **代码要完整**：老师展示的完整函数照截图抄全（看不清的地方标出来），并写出运行结果；只展示了片段的，说明缺了哪部分。
- **老师的口头补充也是内容**：易错点、“为什么这样设计”、与前后课的联系、考试怎么考、作业要求，都要写进去。
- **长度服从内容**：一节 90 分钟的课，内容密的笔记写到几千字很正常；不要为了“简洁”删掉讲过的内容，要删的是重复、空话和关于出处的声明。

## 怎样写得像人写的

| 别这样写 | 这样写 |
|---|---|
| 老师用三角形和龙的例子说明，创造并不是无中生有，也不是对现实逐项复印。 | 认识有创造性：三角形是从具体物体中抽象出来的；龙把多种动物的特征拼在一起。 |
| 这是根据本课结构推导，不是课堂给出的复杂度结论。（写在 AI 补充里） | （直接写结论。放在 AI 补充框里，本身就说明了它不是课上讲的） |
| 课堂要求课后运行课件源代码，并非本节展示了运行终端。 | 课后：运行课件里的源代码，自己跟踪一遍。 |
| 注意调用树有很多结点，不表示这些活动记录同时都在栈中。 | 同一时刻栈里只有从根到当前结点这一条路径上的活动记录。 |
| 重点不是背代码，而是跟踪每层参数、返回位置和中间结果。 | （删掉。这类总结句不提供信息） |
| ……逐层回传。{t 11:08:27} {t 11:10:49} {t 11:11:22} | ……逐层回传。{t 11:08:27} |

具体规则：

1. **写知识，不写课堂经过。** 少用“老师讲了/老师用……说明/课堂提醒”。只在老师本人的态度有信息量时提老师：强调的重点、说会考、个人经验、布置的作业。
2. **出处靠排版，不靠声明。** 正文是课堂内容；`> [!tip] AI 补充` 是你补充的；`> [!quote] 资料` 是资料原文。正文里不要出现“以截图为准”“未伪造”“不补造”“并非课上讲的”“如实保留”这类话。
3. **素材缺口只说一次，说在受影响的地方。** 例如在该小节开头写“（这段没有录音，按幻灯片整理）”。截图里看不清的代码写“（截图看不清）”，转写拿不准的写原文加“（转写不清）”。
4. **少用否定对比。** “不是 A 而是 B”“A 不等于 B”“不要把……理解成……”只在老师本人强调这个区分、或这是常见考点时使用，其余直接写正面结论。
5. **时间点要少。** 每个小节或要点放 1 个，放在这段内容开始的地方，读者点击后从这里开始看。不要每句话都挂。
6. **截图挑着用。** 只插文字说不清的：最终版代码、图表、板书、关键幻灯片、演示过程图，一般 6–15 张，放在相关文字后面，不要连着堆。
7. **能用结构就别用长句。** 步骤用有序列表；对比用表格；代码用带语言标记的代码块，要完整可读；公式用 LaTeX；定义加粗关键词。段落 2–4 句。
8. **平实的句子。** 像讲给同学听。删掉不提供信息的总结句和过渡句（“这为后续学习打下基础”“主线是……”“本节的核心在于……”）。
9. **AI 补充要少而准。** 每篇 0–3 个，只放真正有帮助的解释、类比、反例或推导，不写“这不是课堂内容”。
10. **标题 ≤ 20 字，写主题。** 不写课程名、日期、周次（文件名里已经有日期和周次）。

`lw note save --check` 会对漏掉的讲课时段、时间点过密、标题过长、自证式措辞、截图过多等给出“写作提醒”，改完再保存。

## 按课程类型的重点

- **编程**：老师演示的关键代码（以截图逐字核对，只抄截图里能确认的部分）；操作步骤（新建什么类、怎么运行）；运行结果与报错原因；为什么这样写；常见错误。
- **编程实验**：分开写“老师演示过的”和“实验还要求自己完成的”；配置/环境步骤；踩坑记录。
- **数学/理科**：定义（含条件）、定理、推导的每一步（不跳步）、例题完整解法；公式以板书/幻灯片为准，只有口述的公式标“（口述）”；老师强调的易错点。
- **文科/思政**：论点结构、概念辨析、老师举的例子、明确提到的考点（“会考/简答题”）。适合用“论点 → 理由 → 例子”的层级列表。
- **语言**：词汇短语（附例句）、句型、课文要点、练习答案、老师纠正的错误。

## 引用标记

| 标记 | 含义 | 规则 |
|---|---|---|
| `{t 10:12:48}` | 课堂时间点 | 必须在本课时录像时段内；每段最多 1 个，放在该内容开始处；连写的多个只保留第一个 |
| `{f F012}` | 插入截图 | 只用学习包中列出的 ID；一般 6–15 张 |
| `{m m_xxxx p.3}` | 资料出处 | 页码/幻灯片号写在 ID 后 |

## 真实性（底线）

- 不编造老师的话、时间点、代码和结论。这一条靠 `lw note save` 的引用校验和上面的排版来保证，不需要在正文里反复声明。
- 转写有同音错字：按上下文能确定的直接写正确术语；拿不准的写原文并加“（转写不清）”。
- 截图看不清：写“（截图看不清）”，不要补全代码。
- 老师没讲但你认为重要的内容：放进 `AI 补充`，不要混进正文。
- 平台 AI 摘要只用来定位，不当作老师原话。

## 重新整理 / 换风格

1. `lw note show <课时ID>` 读取当前版本（包含用户在 Obsidian 的修改）。
2. 找出用户自己写的内容（如“我的理解”、批注、补充例子），在新草稿中**原样保留**（可以移动位置，但不改字）。
3. 保存时写 `--style`（如 复习版/精简版/讲义版）。若 `lw note save` 报告“新版本里找不到你补充的这些内容”，补回后再存，不要用 `--allow-drop`，除非用户明确要求删掉。
