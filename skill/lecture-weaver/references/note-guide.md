# 笔记写作指南

目标：让一个不擅长记笔记的学生，下课后能看懂、能复习、能找回老师原话和画面。笔记是在已保存的课堂资料（转写、截图、资料）之上**重新组织**出来的，换模型或换风格时只需要重新读学习包，不需要重新处理录像。

## 分层

1. **课堂资料层**（已由 `lw process` 保存）：带时间的转写、截图与 OCR、平台信息。不要改。
2. **课堂笔记**（`--kind lecture`，每个课时一篇）：按老师讲授的逻辑整理，所有课堂内容可追溯。
3. **按需产物**：复习提纲（`--kind review --key 第7周复习 -c 课程`）、知识卡片（`cards`）、专题（`topic`，如“关系代数除法”“实验三要求对照”）、针对一个问题的讲解（`explain`）。

## 课堂笔记的默认结构（可按课程调整）

```markdown
# <主题>（不要只写日期）

## 本节课在讲什么
3–5 行：主线、与上一讲的衔接（引用上一讲笔记中的概念名即可）。

## 1. <知识块>
老师的讲法、关键结论、例子 {t 10:12:48}
{f F012}

> [!tip] AI 补充
> 课上没讲、但有助于理解的解释/类比/反例。

## 复习自测
3–6 个问题，覆盖本节重点（答案不写或折叠）。
```

“资料说明”（录像段、转写来源、截图数量、课表对应）由 `lw note save` 自动追加，不必手写。

## 按课程类型的重点

- **编程**：完整保留老师演示的关键代码（以截图逐字核对；只抄截图中能确认的部分，截图外的推断要说明）；操作步骤（新建什么类、怎么运行）；运行结果与报错原因；为什么这样写；常见错误。
- **编程实验**：区分“老师演示过的”与“实验还要求自己完成的”；配置/环境步骤；踩坑记录。
- **数学/理科**：定义（含条件）、定理、推导的每一步（不跳步）、例题完整解法；板书/幻灯片上的公式以图为准，口述公式注明“口述”；老师强调的易错点。
- **文科/思政**：论点结构、概念辨析（如“改革与革命”）、老师举的例子、明确提到的考点（“会考/问答题”）。
- **语言**：词汇短语、句型、课文要点、练习答案、老师纠正的错误。

## 引用标记

| 标记 | 含义 | 规则 |
|---|---|---|
| `{t 10:12:48}` | 课堂时间点 | 必须在本课时录像时段内；放在对应句子末尾；同一段可以多个 |
| `{f F012}` | 插入截图 | 只用学习包中列出的 ID；挑有信息量的（代码最终状态、关键幻灯片、板书），一篇 5–15 张为宜 |
| `{m m_xxxx p.3}` | 资料出处 | 页码/幻灯片号写在 ID 后 |

## 诚实原则

- 转写有同音错字：按上下文能确定的直接写正确术语；拿不准的写原文并加“（转写不清）”。
- 截图看不清：写“（截图看不清）”，不要补全代码。
- 某段没有转写或没有录屏：在相应位置说明“这部分只有截图/只有转写”。
- 老师没讲但你认为重要的内容：放进 `AI 补充`，不要混进正文。
- 不要用平台 AI 摘要的句子冒充老师的话。

## 重新整理 / 换风格

1. `lw note show <课时ID>` 读取当前版本（包含用户在 Obsidian 的修改）。
2. 找出用户自己写的内容（如“我的理解”、批注、补充例子），在新草稿中**原样保留**（可以移动位置，但不改字）。
3. 保存时写 `--style`（如 复习版/精简版/讲义版）。若 `lw note save` 报告“新版本里找不到你补充的这些内容”，补回后再存，不要用 `--allow-drop`，除非用户明确要求删掉。
